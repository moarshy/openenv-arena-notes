# Study (2026-10-15): can an environment move the score at all?

68 scored runs from 28 users. Focus: keeping office, and gaining software or math.

## What the runs show
- **Software:** 15/68 runs scored software 1, and none scored 2. rca-umb puts the rate at 29% of runs, about the same for very different environments. That includes runs with no code tasks at all, such as MetaHarness and the null-like controls.
- **Math:** 1/68. That one was ours (v3), and it did not replicate (v4).
- **Office:** 33/68 runs kept office 2, and 35 dropped to 1. rca-umb: "office one sure task plus one coin flip".
- **Industrial:** behaves like two coin-flip tasks (0/1/2 = 11/22/12 across the first 45 runs).
- **Totals:** the untrained model's expected score is about 2.9, and trained runs average 2.98. **No entrant differs from chance** (rca-umb permutation test, p = 0.6).

## Controls run by other entrants
| run | what training did | private score |
|---|---|---|
| naklitechie null control | Nothing: zero gradient | 1/40 |
| rca-umb collapse v5 | Learned to quit early (reward 0.48 → 0.76, about 3 calls instead of 6) | 3/40 |
| ruv focus4, twice | Identical request submitted twice | 4/40, then 2/40 |
| our v3 / v4 | Identical image and tasks | 4/40, then 3/40 |
| rca-umb collapse v6 (hard) | Reward only for ending on the first action | pending: if 0–1, training reaches the score; if 2+, it doesn't |

**Reading:** so far nothing shows that within-run training moves the private score, in either direction. The hard-collapse result will be the cleanest test yet.

## Why training might not reach the score: the interface hypothesis
dnakhla found the operator's own smoke-test Spaces (`benchflow/arena-tb2-*`, `benchflow/openenv-smoke-fix-git`). They serve Terminal-Bench-2 tasks through OpenEnv's `tbench2_env`:
- **Actions:** `{action_type: exec | write_file | evaluate, command, file_path, content}`
- **Observations:** `{instruction, output, success, error}`
- **The instruction is repeated in every observation, and output is never truncated.**
- **Limits:** `completion_tokens` 4096, `context_tokens` 8192, 32 tool calls.

rca-umb adds that the domain IDs are SkillsBench v1.1's taxonomy verbatim, and that its tasks are packaged the same way. Frontier agents use about 1.6M tokens per SkillsBench trial.

**If heldout-v2 runs like that:**
- The untrained 27B gets about 5–6 short actions before the budget ends the episode.
- It solves only the few short tasks, which is the ~4/40.
- Training JSON answers to synthetic questions doesn't practise what those tasks need: short shell work on real files, an exact output file, and economy under a tight budget.
- Every environment so far, ours included, trained with different schemas and looser budgets.

**rca-umb's further evidence:** strict one-JSON-object parsing fits arena training rewards better than lenient parsing. The model "breaks format exactly when a task makes it reason about code". That may be why software tasks score 0.

## A risk to our environment: dropping privileges per command
ajinkyamulay's v6 Repo Repair tasks scored about 0.02 in the arena, because "where a container cannot switch users every call failed" (setuid blocked). rca-umb's setuid worked on 2026-10-12, so it may depend on the node or the date. **Workbench runs every command as `agent` through setuid.** We need a fallback, and to check v5's training reward on the dashboard.

## Implications for us
1. **Leaderboard:** on this evidence the row grows mainly by drawing domains across runs (software 1 at about 29% per run). Any non-harmful environment is a ticket, so submitting daily is the main lever.
2. **Learning, and a chance at a real effect:** the strongest untested hypothesis is that the *interface and budget* mismatch hides training gains. An environment that mirrors `tbench2_env` exactly (`exec` / `write_file` / `evaluate`, instruction repeated, 4096/8192 budget, real files, a pytest-checked output) is the cleanest test, and it uses everything we built.
3. **Hygiene:** a setuid fallback in the sandbox, plus a strict-parsing calibration mode, since it predicts arena rewards better.
